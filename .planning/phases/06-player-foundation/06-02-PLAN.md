# Plan 06-02: DeviceProfile & PlaybackPlanner Stream Negotiation

## Objective

Build the hardware capability detector (`DeviceProfile`) and dynamic stream negotiation pipeline (`PlaybackPlanner`). The planner analyzes media stream metadata (container, video codec, audio codec, resolution, bitrate) and client hardware capabilities to determine the most efficient playback mode: **Direct Play** (raw direct stream with zero server overhead), **Direct Stream** (re-muxing container without re-encoding codecs), or **Transcoding** (HLS dynamic streaming). It constructs sanitized playback URLs and redacts sensitive tokens in all diagnostic output.

    1. Create `src/features/player/deviceProfile.ts`:
       - Define `DeviceProfile` interface:
         - `supportedContainers: string[]` (e.g. `mp4`, `m4v`, `mkv`, `webm`, `ts`)
         - `supportedVideoCodecs: string[]` (e.g. `h264`, `hevc`, `h265`, `vp9`, `av1`)
         - `supportedAudioCodecs: string[]` (e.g. `aac`, `mp3`, `ac3`, `eac3`, `flac`, `opus`)
         - `maxResolution: { width: number; height: number }`
         - `maxBitrate?: number`
       - Export `getDefaultDeviceProfile(platform?: string): DeviceProfile` with sensible defaults for iOS/Android native platforms running Media3 / AVPlayer.
    2. Create `src/features/player/playbackPlanner.ts`:
       - Define `PlaybackPlan`:
         - `mode: "direct-play" | "direct-stream" | "transcode"`
         - `url: string`
         - `mediaSourceId?: string`
         - `videoCodec?: string`
         - `audioCodec?: string`
         - `container?: string`
         - `reason: string`
       - Export `createPlaybackPlan(options: PlaybackPlanOptions): PlaybackPlan`:
         - Options: `{ item: MediaItem; serverUrl: string; token: string; deviceProfile?: DeviceProfile }`
         - Inspects `item.mediaStreams` to determine video and audio codecs.
         - Checks codec & container support against `deviceProfile`:
           - If container and video codec and audio codec supported -> `direct-play`:
             - URL: `${serverUrl}/Videos/${item.id}/stream?static=true&api_key=${token}`
           - Else if video codec and audio codec supported but container unsupported -> `direct-stream`:
             - URL: `${serverUrl}/Videos/${item.id}/stream?videoCodec=copy&audioCodec=copy&api_key=${token}`
           - Else -> `transcode`:
             - URL: `${serverUrl}/Videos/${item.id}/master.m3u8?videoCodec=h264&audioCodec=aac&api_key=${token}&transcodingProtocol=hls`
       - Export helper `getSanitizedPlaybackUrl(url: string): string` redacting `api_key` and token parameters using `sanitizeData`.
  </action>

    - `createPlaybackPlan` correctly chooses direct-play, direct-stream, and transcode based on mediaStreams
    - Redacted URL utility prevents secret leakage
