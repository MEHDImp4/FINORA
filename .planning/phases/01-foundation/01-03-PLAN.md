# Plan 01-03: Secure Storage Layer & Finora Design System Foundation

## Objective

Implement the secure storage adapter wrapping `expo-secure-store` for sensitive authentication credentials and `AsyncStorage` for non-sensitive preferences, and build the foundational Finora Design System tokens (cinematic dark theme, typography, spacing) and UI primitives (`FinoraScreen`, `FinoraButton`, `FinoraIconButton`, `FinoraText`) delivering touch response under 50ms.

---

<task id="01-03-01">
  <read_first>
    - .planning/phases/01-foundation/01-CONTEXT.md
    - .planning/PROJECT.md
  </read_first>
  <action>
    1. Create `src/core/security/storage.ts`:
       - `SecureTokenStorage`: Interface and implementation using `expo-secure-store` with methods `setToken(key, value)`, `getToken(key)`, `deleteToken(key)`, `clearAllTokens()`.
       - `UserPreferencesStorage`: Interface and implementation using `@react-native-async-storage/async-storage` for non-sensitive preferences (`theme`, `playbackSettings`, `activeServerId`).
       - Guard condition: Throws `StorageError` if an attempt is made to write a password or sensitive token to `UserPreferencesStorage`.
    2. Write unit tests in `src/core/security/__tests__/storage.test.ts`:
       - Verifies `SecureTokenStorage` writes, reads, and deletes tokens properly.
       - Verifies `UserPreferencesStorage` stores serialized preference records.
       - Verifies security invariant that sensitive token keys are blocked from unencrypted storage.
  </action>
  <acceptance_criteria>

  </acceptance_criteria>

## Verification & Must-Haves

### Truths
- Sensitive tokens are stored securely in hardware-backed storage
- Passwords are never saved in storage
- Design system tokens define complete dark cinematic theme
- FinoraButton provides immediate (<50ms) visual response upon touch

### Prohibitions
- No storing access tokens in plain unencrypted AsyncStorage
- No custom arbitrary colors in primitives bypassing design tokens
