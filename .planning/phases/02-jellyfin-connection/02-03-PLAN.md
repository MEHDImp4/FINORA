# Plan 02-03: Multi-Server Management, Session Revocation & Server Diagnostics

## Objective

Support multi-server registration and switching without credential cross-contamination, implement clean session revocation with remote server logout and cache clearing, and build the live Server Diagnostics tool in the Settings screen.

---

## Tasks

<task id="02-03-01">
  <read_first>
    - src/core/jellyfin/authRepository.ts
    - src/core/security/storage.ts
    - .planning/phases/02-jellyfin-connection/02-CONTEXT.md
  </read_first>
  <action>
    1. Create `src/core/jellyfin/serverManager.ts`:
       - Define models `ServerRecord` and `AccountRecord`.
       - Manage saved servers and user profiles in `UserPreferencesStorage` with key `finora_servers_list`.
       - Implement `switchAccount(serverId: string, userId: string)`:
         - Retrieves targeted server URL and account info.
         - Loads matching token from `SecureTokenStorage` (`finora_auth_token_${serverId}_${userId}`).
         - Sets active session and reconfigures `jellyfinClient`.
         - Validates that no credentials leak across different accounts or servers.
       - Implement `logout(serverId: string, userId: string)`:
         - Sends `POST /Sessions/Logout` to Jellyfin.
         - Deletes the token from `SecureTokenStorage`.
         - Removes or deactivates the session from active state.
         - Resets active server headers.
    2. Create `src/stores/serverStore.ts` using Zustand to track registered servers and provide reactivity to UI.
    3. Create unit tests `src/core/jellyfin/__tests__/serverManager.test.ts` testing multi-server registration, isolation between accounts, switching, and token revocation upon logout.
  </action>
  <acceptance_criteria>
    - Multiple server profiles can be persisted with isolated tokens
    - Switching accounts points client to target server and correct authorization token
    - Logout calls `/Sessions/Logout` and deletes secret from SecureTokenStorage
    - Unit tests in `serverManager.test.ts` pass
  </acceptance_criteria>
  <verify>
    <automated>npx jest --testPathPattern=serverManager.test.ts</automated>
  </verify>
</task>
