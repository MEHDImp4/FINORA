# Plan 02-02: Authentication Flow, Zero Password Retention & Session Restoration

## Objective

Implement the Jellyfin authentication flow in `AuthRepository`, guarantee that plain-text passwords are completely purged from memory immediately post-call, store authentication tokens exclusively in `SecureTokenStorage`, and support transparent session auto-restoration upon application launch.

---

## Tasks

<task id="02-02-01">
  <read_first>
    - src/core/security/storage.ts
    - src/core/network/httpClient.ts
    - src/core/jellyfin/clientInfo.ts
    - src/core/jellyfin/jellyfinClient.ts
    - .planning/phases/02-jellyfin-connection/02-CONTEXT.md
  </read_first>
  <action>
    1. Create `src/core/jellyfin/authRepository.ts`:
       - Define interfaces `LoginCredentials`, `AuthSession`, `UserSummary`.
       - Implement `AuthRepository` class:
         - `authenticate(credentials: LoginCredentials, serverUrl: string): Promise<AuthSession>`:
           - Immediately copies necessary fields and ensures password string is set to null/cleared locally once sent.
           - Calls Jellyfin `POST /Users/AuthenticateByName`.
           - Extracts `AccessToken`, `User.Id`, `User.Name`.
           - Persists token into `SecureTokenStorage` with key `finora_auth_token_${serverId}_${userId}`.
           - Persists active session record in `UserPreferencesStorage` (`finora_active_session`).
           - Updates `jellyfinClient` headers.
           - Returns sanitized `AuthSession` object without password.
         - `restoreSession(): Promise<AuthSession | null>`:
           - Reads active session descriptor from preferences.
           - If found, loads token from `SecureTokenStorage`.
           - Verifies token validity by requesting `/System/Info` or `/Users/Me`.
           - If valid, configures client and returns session.
           - If 401 or invalid, cleans up stored session and returns `null`.
    2. Write unit tests in `src/core/jellyfin/__tests__/authRepository.test.ts` verifying:
       - Password is never returned in session object or logged.
       - Token is stored in `SecureTokenStorage` and not plain storage.
       - Successful login sets up session.
       - Session restoration handles valid and expired tokens gracefully.
  </action>
  <acceptance_criteria>
    - `authenticate` calls `/Users/AuthenticateByName` with FINORA client headers
    - Passwords are discarded immediately post-auth
    - Tokens are saved to `SecureTokenStorage`
    - Unit tests in `authRepository.test.ts` pass
  </acceptance_criteria>
  <verify>
    <automated>npx jest --testPathPattern=authRepository.test.ts</automated>
  </verify>
</task>
